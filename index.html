03 / ENGINEERING

Interesting is easy.
Useful is harder.

We care about the parts that make software understandable after the demo: explicit maturity, documentation, safe defaults, human control and evidence for the claims being made.

01

Readable

Architecture and project intent should be understandable without reverse-engineering the entire repository.

02

Reviewable

Security and maturity statements should be specific enough to challenge and verify.

03

Controllable

High-impact automation should leave room for human approval and clear operating boundaries.

04

Adaptable

Public tools should be useful as foundations, not locked to one hosting provider or one way of working.

Open code is more useful when it gives someone else a starting point.
